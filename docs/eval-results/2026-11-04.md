**Date:** 2026-11-04
**Model:** Random Forest Classifier
**Dataset:** Credit Card Fraud Detection

## 1. Evaluation Protocol

The dataset was divided chronologically:

- Training: 70%
- Validation: 15%
- Test: 15%

The Random Forest was selected using validation performance.

The operating threshold was selected using validation data by minimizing classification cost.

- Missed fraud cost (False Negative): 50
- False alarm cost (False Positive): 1
- Selected threshold: 0.1128755386620629
- Validation cost: 357

The test set was not used for model selection or threshold optimization.

## 4. Validation vs Test

| Metric                          | Validation |   Test |
| ------------------------------- | ---------: | -----: |
| PR-AUC                          |     0.8701 | 0.7686 |
| ROC-AUC                         |     0.9730 | 0.9720 |
| Recall at selected threshold    |     0.8929 | 0.7885 |
| Precision at selected threshold |     0.4673 | 0.3832 |

The test PR-AUC is lower than validation PR-AUC. This indicates weaker precision-recall performance on the later chronological data.

ROC-AUC remains relatively stable. Temporal distribution differences are a possible explanation, but further investigation would be required to confirm this.

## 5. Limitations

- The false-negative and false-positive costs are assumed business costs, not measured real-world financial losses.
- The dataset contains anonymized PCA-derived features.
- The results do not establish production readiness.
- The test evaluation represents one chronological holdout, not guaranteed future performance.

## 6. Test Set Usage

The test set was evaluated once using the pre-selected Random Forest model and validation-derived threshold.

No threshold tuning or model selection was performed using test results.

The test results are preserved in `artifacts/2026-11-04_random_forest_v1/evaluation.json` under the `test` key.
